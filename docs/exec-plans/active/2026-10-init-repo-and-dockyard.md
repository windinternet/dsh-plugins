# 执行计划：初始化仓库并交付 dockyard 插件

## 目标

把空仓库变成一个能持续承载 DSH 插件的工程底座，并交付第一个真实插件 dockyard。

判定完成的验收标准（可机械核对）：

1. `pnpm check` 全量通过，且它覆盖格式、lint、类型、清单、文档、密钥、测试七类检查。
2. `pnpm create-plugin` 能从注册表条目生成可安装的插件骨架，且生成物通过语法与清单校验。
3. dockyard 插件的 Host 工具能被注册，进程生命周期与日志行为有测试覆盖。
4. 仓库内不存在任何真实密钥；提交前钩子与 CI 都会拦截。
5. 文档结构满足机械检查：入口完整、链接可达、生成物最新。

## 背景与约束

- 仓库是公开的，密钥与隐私保护是硬要求。
- 宿主基线 `@deepseek-ai/dsh@0.2.0-rc.2`，插件框架是 Cordis。
- 宿主内部包不在公开 npm 上，因此插件不能把它们声明为依赖。
- UI 插件禁止引用任何 `@deepseek-ai/dsh-client-*` 包，样式只能用 `--dsw-alias-*` token。
- 用户明确要求：不修改既有的 dockyard 项目，只借鉴其目标与思路重新实现。

## 这次验证推翻的两个假设

写代码时的两个推断都是错的，只有真实安装才暴露出来：

1. **"插件能凭空解析宿主内部包"——错。** 现象是安装看起来成功、启动报一行
   `failed to import`。修正为把 `@deepseek-ai/dsh-tools` 与 `@deepseek-ai/schemastery`
   声明为真实依赖（精确版本），并且**必须用 `file:` 或 registry spec 安装**：
   `link:` 不解析依赖树，`workspace:*` 在外部 profile 里必然失败。
2. **"可以探测式读取 `ctx.baseDir` / `ctx.webServer`"——错。** 未声明 inject 的服务属性
   会抛 `cannot get property "X" without inject`，而且**发生在激活期**，插件直接不激活。
   修正为可选服务用 `ctx.inject([...], cb)`，路径用环境变量与家目录推导。

两条结论都已写入 [`dsh-plugin-api.md`](../../references/dsh-plugin-api.md)。

## 决策日志

| 日期       | 决策                                         | 理由                                                                                 |
| ---------- | -------------------------------------------- | ------------------------------------------------------------------------------------ |
| 2026-10-10 | 用 pnpm workspace + Turborepo                | 用户选定；为插件数量增长预留任务编排能力                                             |
| 2026-10-10 | 插件用纯 JS，共享库也用纯 JS + JSDoc         | DSH 插件不做打包；引入构建步骤会让"改完就能装"退化                                   |
| 2026-10-10 | 注册表用 JSON 而不是各包自声明               | 中心清单让一致性可被一个脚本双向校验，也能生成文档表                                 |
| 2026-10-10 | 不声明宿主内部包为依赖                       | 它们不在公开 npm 上，声明会让 `pnpm install` 直接失败；改为运行时解析 + 本地类型存根 |
| 2026-10-10 | 宿主状态文件用原子替换的 JSON，不引入 SQLite | 写入量很小；每多一层存储就多一处可能不一致的状态                                     |
| 2026-10-10 | 进程停止采用"温和终止 → 升级强杀 → 确认消失" | 只发信号就返回会让面板谎报已停止，用户下次启动撞端口                                 |
| 2026-10-10 | 宿主重启后把 running 降级为 unknown          | 无法区分"已退出"与"成了孤儿"，谎报运行中比未知更糟                                   |
| 2026-10-10 | `docs/generated/` 排除出 Prettier 范围       | 生成器与格式化工具会互相覆盖，导致 docs:check 反复失败                               |
| 2026-10-10 | 引入最小的宿主类型存根                       | 没有存根时入口文件的类型检查整体失效，而入口最需要检查；存根的限制写在文件头         |
