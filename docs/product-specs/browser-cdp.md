# browser-cdp 产品规格

## 一句话

让智能体自己开一个**真的浏览器**，用 CDP 直接读页面、点按钮、看截图——不需要图像识别猜坐标，
不需要人肉搬运页面内容。

## 问题

Web 相关的活儿（自动化测试、抓取、复现线上问题、验证自己的前端改动）在智能体工作流里是刚需，
但现状是三选一，且都别扭：

1. **纯 HTTP 抓取**（`web_fetch`）：拿不到渲染后的 DOM，登录态、SPA、交互流程全废。
2. **视觉自动化**（截图 → 图像识别 → 算坐标 → 模拟鼠标）：又慢又脆。分辨率、滚动位置、
   字体渲染任何一项变化都会让坐标失效，而且每一步都要多花一次多模态推理。
3. **外部浏览器 + 手工驱动**：人得在旁边点，智能体插不上手。

而浏览器自己早就把答案摆在桌面上了：**CDP（Chrome DevTools Protocol）**。
它是浏览器内置的、稳定的、结构化的控制协议——读 DOM 是读 DOM，点击是真实输入事件，
截图是协议原生能力，根本不需要"看图猜位置"。

DSH Desktop 内置的 Sidebar 浏览器（Electron `<webview>`）**不能**用于此目的，这是查阅官方
材料后的确定结论，不是偷懒：官方决策记录明确写着该实现"不提供 remote-debugging 端点，
也不提供 browser-use 集成"，未来的自动化提供方需要"一个已认证、按 target 授权的 broker"，
而不是访问全部应用 target；且插件运行在 `ELECTRON_RUN_AS_NODE` 的宿主子进程里，
拿不到任何 Electron 对象。官方认可的自动化形态是**由提供方自己启动或接入一个 Chromium**
（`ctx.browserUse` 接缝下的三个官方提供方全部如此）。

所以本插件做的是官方认可的那件事，但不依赖任何外部 MCP 服务器或 npm 依赖。

## 目标（非目标同样重要）

**做：**

1. 自动发现本机 Chromium 系浏览器，以 `--remote-debugging-port` 启动一个**受管的**实例。
2. 端口**自适应**：在配置的范围内挑一个真正可用的（绑定探测 + HTTP 探测双重确认），
   避开常用端口段。
3. 用**独立且可持久**的 profile，登录态跨重启保留，且完全不污染用户自己的浏览器会话。
4. 提供一套**结构化**的浏览器工具：导航、可交互元素快照、文本/HTML 读取、真实鼠标键盘输入、
   截图、等待、网络与控制台观测。
5. 随插件提供一份**方法论技能**（什么时候用哪个工具、怎么避免脆弱的定位、怎么验证动作生效），
   通过 `ctx.skills` 注册为 runtime skill。
6. 进程与状态可解释：拿不到证据时如实报告，不谎报"运行中"。

**不做：**

1. **不做图像识别定位。** 位置来自 DOM 几何信息，截图只用于人类查看与像素级验证。
2. **不接管 DSH 内置 Sidebar 浏览器。** 这是**已核实的定论**，不是暂缓：要自动化它就得让整个
   Electron 实例开 CDP，而插件拿不到 `app.commandLine`、启动期开关也来不及追加、直接改
   `lib/main.js` 会被 asar 完整性校验与代码签名拦住（三条证据见
   [`../references/chromium-cdp-facts.md`](../references/chromium-cdp-facts.md)）。
   即便从界面侧绕过去驱动那个 `<webview>`，也没有 CDP，等于放弃截图/网络/控制台/无障碍树。
   本插件用官方认可的"自管 Chromium"形态，那也是官方三个 browser-use 提供方的一致形态。
3. **不打包 Playwright / Puppeteer。** 它们把 CDP 又包一层，还要几十到几百 MB 的依赖。
   直接用 CDP + Node 内置 WebSocket，零第三方依赖。
4. **不做多用户、远程、集群。** 这是本机单用户工具。
5. **不提供绕过反自动化检测的能力。** 不做指纹伪装、不注入 stealth 脚本。

## 数据流向

`local-only`。所有数据留在本机：

- 浏览器进程、profile、截图全部在本机文件系统。
- CDP 通道是 `127.0.0.1` 上的回环 WebSocket，不出本机。
- 被访问的**网页**当然会联网——那是浏览器在被使用，不是插件在发遥测。
  插件自身不向任何第三方端点发送数据。

## 用户可见行为

### 启动与端口

- 第一次调用浏览器工具时自动启动；也可显式 `browser_open`。
- 端口在 `portRange`（默认 `24000-24060`）内自适应，选中后固定给本次会话，
  并在返回值与状态面板里**明确报告实际端口**——端口不是猜出来的，是探测出来的。
- 浏览器可执行文件按 `executablePath` → `browserPaths` → 平台常见安装位置 → `PATH` 的顺序查找；
  找不到时明确报错并列出找过的位置，而不是抛一句"启动失败"。
- 渲染进程真的崩了（拿不到可用 target 或收到崩溃事件）时，**回退到关闭沙箱重试一次**，
  并在返回值里如实说明用了这个回退——而不是静默降级或谎报成功。
- 默认无头运行，`headless: false` 可看见窗口；`headlessMode` 可配置。

### 工具行为

每个浏览器工具都必须做到"动作完成或明确失败"，不做乐观返回：

| 工具                 | 承诺                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------- |
| `browser_open`       | 启动/接入受管浏览器并打开页面，返回真实端口、浏览器版本与页面标题。                       |
| `browser_navigate`   | 导航并等到可交互（DOM 就绪/DOMContentLoaded/load），返回最终 URL 与标题。                 |
| `browser_snapshot`   | 返回带**稳定引用号**的可交互元素清单（标签、文本、角色、是否可用），供后续点击/输入定位。 |
| `browser_content`    | 按 `text`/`html` 读取页面内容，可选限定到某个引用或选择器。                               |
| `browser_get`        | 读取一个元素的属性/值/可见性。                                                            |
| `browser_click`      | 用**真实输入事件**（`Input.dispatchMouseEvent`）在元素中心点击，回读动作后的状态。        |
| `browser_type`       | 聚焦后逐字符输入（真实键盘事件），支持清空与回车提交。                                    |
| `browser_key`        | 发送按键与组合键（如 `Enter`、`Cmd+A`）。                                                 |
| `browser_wait`       | 等待选择器出现/消失、文本出现、或导航完成；超时即超时，不假装成功。                       |
| `browser_screenshot` | 截图落盘并返回绝对路径与像素尺寸（人类与像素级验证用）。                                  |
| `browser_eval`       | 在页面里执行 JS 表达式（可 await），返回值按值序列化。                                    |
| `browser_network`    | 读取本次会话记录到的请求（方法、URL、状态码、失败原因、耗时）。                           |
| `browser_console`    | 读取 console 消息、页面异常与未处理 Promise 拒绝。                                        |
| `browser_tabs`       | 列出/新建/选中/关闭页面标签。                                                             |
| `browser_close`      | 关闭受管浏览器并等待进程真的消失。                                                        |

### 失败与边界

- 引用号过期（页面已变化）时明确要求重新 `browser_snapshot`，不猜一个位置点下去。
- 元素不在视口内时先滚动到元素再点击，并在结果里说明发生了滚动。
- 页面 JS 抛错不让工具崩溃：错误作为观测结果返回。
- 浏览器被用户手动关掉后，下一次调用必须能察觉并如实报告，而不是继续说"运行中"。

### 面板

当宿主组合了 HTTP 服务时，输入框下方停靠区显示一行状态：`browser-cdp · 未启动/端口 24000/已关闭`。
点击展开显示浏览器版本、profile 目录、当前页面、CDP 端点，并提供"打开页面"的只读信息。
数据来自只读同源路由 `/plugin/browser-cdp/status`，只接受本机来源。

## 验收标准

1. `pnpm check` 全绿（格式、lint、类型、清单、文档、密钥扫描、测试）。
2. 单元测试覆盖纯逻辑：端口选择、浏览器发现、引用号生成与过期、快照格式化、CDP 帧解析、
   进程存活判定。
3. **真实端到端验证**（脚本 + 人工各一次）：以真实浏览器跑通
   启动 → 导航 → 快照 → 真实点击 → 读回变更 → 截图 → 关闭，且端口是探测出来的。
4. 真实安装：通过宿主 `plugin_manager` 的 `install_bundle` 装进一个干净 profile，
   安装结果无 `failed to import`，`cordis_inspect_query` 能看到插件行激活。
5. 不存在任何出网请求代码路径（除被访问页面自身）；无硬编码密钥；
   日志与返回值经过脱敏。

## 已知非目标与限制（写在前面，避免误解）

- **不能驱动 DSH 内置 Sidebar 浏览器。** 见上文，官方无此接缝。
- **不保证通过所有反自动化站点。** 受管实例是标准 Chromium，行为可被检测。
- **macOS 上若宿主运行在受限沙箱里**，Chromium 渲染进程可能起不来，此时会走
  "关闭浏览器沙箱重试"的回退路径；这在返回值里会被明确标注。
- **不做跨会话的浏览器共享。** 浏览器归插件所有，会话之间共享同一个受管实例；
  多会话同时操作同一页面时后到者覆盖先到者，这是本机单用户工具的合理边界。
