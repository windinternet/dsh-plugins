# dockyard 产品规格

## 一句话

在本机把"随手 `npm run dev` 起了一堆服务"这件事，变成**可观测、可解释、可收回**的托管。

## 问题

本机开发时同时跑十几个服务的现状是：

- 进程散落在多个终端窗口里，谁在跑、跑的是什么、占了多少资源，没人说得清。
- 日志随终端滚动消失，出问题时已经看不到现场。
- 端口冲突时不知道被谁占了。
- 重启机器后忘记哪些服务原本是开着的。
- 关掉终端等于杀掉服务，或者反过来，服务活着但找不到它的终端了。

现有的进程管理器（pm2 之类）解决了一部分，但它们是**黑盒**：配置格式自成一套、
状态不可读、出问题时只能猜。而这个仓库的用户是智能体与人协作——**黑盒是不可接受的**，
因为智能体无法从黑盒里推理出发生了什么。

## 目标（非目标同样重要）

**做：**

1. 扫描本机项目目录，识别出哪些是可运行的应用（而不是把所有目录都当应用）。
2. 受监管地启动、停止、重启应用；进程归插件所有，终端关掉不影响服务。
3. 日志落**文件**，可以按需读取和跟踪，而不是只活在终端缓冲区里。
4. 状态对人和智能体都可读：在跑什么、从哪个目录、什么命令、最近发生了什么。
5. 在 DSH 界面里有一个面板，能看状态、看日志、做启停。

**不做：**

1. 不做容器编排、不做集群、不做远程部署。这是本机工具。
2. 不替代 `npm run dev` 本身——它托管的正是这个命令。
3. 不引入自己的守护进程和 Web 服务器。DSH 宿主进程就是守护进程，
   DSH 的界面就是面板。多一层进程只会多一处不一致。
4. 不做自动发现以外的自动决策。识别不准时暴露给用户选，而不是猜。

## 数据流向

`local-only`。所有数据都留在本机：

- 不发起任何出网请求。
- 日志写在插件自己的数据目录下的文件里。
- 元数据（项目、应用、运行记录）写在本机存储里。
- 面板与 Host 之间的通信走 DSH 自己的宿主通道，不出本机。

## 用户可见行为

### 扫描

用户在发现页点一次「扫描」，选择一个目录，就自动开始扫描；不再手输路径。扫描结果
归一化成 **项目 → 语言生态分组 → 可运行应用** 三层：

- **项目判定**：扫描根自身是 git 仓库时只算一个项目；否则看直接子目录，有 `.git` 或有
  项目清单（`pom.xml`、`package.json`、`pyproject.toml`、`go.mod`、`Cargo.toml`、
  `composer.json`、`pubspec.yaml` 等）的算项目。没有 git 也没有清单、但直接子目录里有
  仓库的普通文件夹是**容器**，只展开一层：子仓库成为项目，容器本身不算项目。
  更深的嵌套 `.git` 不单独成为项目。
- **生态分组**：每个项目独立识别 Java-Maven、Java-Gradle、Node.js、PHP-Composer、
  Flutter、Go、Rust、Python、Shell 等生态；同一项目可有多组，单生态不渲染分组层。
  Node.js 按实际 lockfile / `packageManager` 区分 pnpm / yarn / npm / bun。
- **可运行应用**：只把能作为长期服务启动的入口算应用（Spring Boot 模块、Node 启停脚本、
  Laravel/Symfony、Flutter、Go main、Rust bin、Python 入口、Shell 脚本），
  library 和构建脚本不伪装成应用。

每个应用必须带上**判定理由**：依据哪个文件、什么规则、识别成什么类型。
理由是必需的，因为"为什么它认为这是应用"正是用户和智能体都需要的信息。

### 生命周期

- 启动：以应用的工作目录为 cwd 启动进程，采集 stdout 与 stderr 到日志文件。
- 停止：先发终止信号，超时后升级为强杀。**必须真的等进程结束**，不能发完信号就返回。
- 重启：停止后启动，且保持原有的启动参数。
- 状态：每个应用有一个明确的状态（未启动 / 启动中 / 运行中 / 已停止 / 异常退出），
  并记录最近一次状态变化的原因。

### 周期同步

- 每 5 分钟（可配置）对已托管项目重扫一次，也支持手动触发。
- 新应用自动加入托管但不自动启动；命令变化保留旧参数并标记需重启；
  磁盘上消失的应用标记失联，保留记录/日志/指标；重新出现时恢复。
- 同步不自动重启、不删除旧记录，避免打断调试或丢历史。

### 外部进程与非托管应用

- 对已托管项目检测 cwd 在项目根下、但不是 dockyard 启动的进程，并尽量匹配回具体应用；
  匹配依据是 cwd、应用目录/名称、`-pl`、`--filter` 等显式模块选择。无法唯一匹配的进程
  标为「未识别外部进程」，不做自动接管。
- 已由 dockyard 启动的应用树（启动器及其子进程）不会被算作外部进程，避免同一个应用在托管/非托管之间跳动。
- 匹配到的应用以**非托管**状态出现在服务页：可以读取状态、CPU/内存、监听端口；
  无法读取它的 stdout/stderr 日志（终端输出不在插件手里）。
- 非托管应用可以停止（只终止匹配到的外部进程），也可以重启；**重启等价于手动接管**：
  停止外部进程后由 dockyard 启动应用，从此日志、指标、启停都归插件管理。
- 接管是手动的，分三个入口：服务页顶部「一键接管」处理全部非托管应用；项目卡
  「一键接管」只处理本项目；应用行的「停止/重启/接管」只处理该应用。
- 接管只针对匹配到的外部进程，不会因为某个应用被接管就启动项目里的其他应用，
  也不会自动接管、自动启动任何东西。
- 发现依赖 `ps` / `lsof`；不支持的环境只报告“无法枚举”，不误杀。

### 进程独立性与日志

- 被 dockyard 启动的应用由独立启动器接管：应用不是插件或 DSH 的子进程，DSH 关闭后
  继续运行；启动器写文件日志，按 `OUT` / `ERR` / `SYS` 标记来源，并按大小轮转。
- 因此停止/重启走的是启动器进程组；插件卸载默认不杀应用，只把状态如实标为 unknown。

### 保活与重试（只对手动操作生效）

- **任何情况下都不会自动启动未运行的应用。** 宿主启动、周期同步、扫描、发现都不会拉起应用；
  只有用户（或智能体代为执行）的手动启动/接管才会启动进程。
- 守护只在两种手动操作后开启：通过本插件启动应用、通过本插件接管已运行的应用。
- 守护在以下情况关闭：用户手动停止、应用被移除/失联、保活策略被关闭、自动重试次数用尽。
- 策略字段：是否启用、重试次数上限、退避基数、单次退避上限、稳定运行重置时间。第 n 次
  自动重试的延迟为 `min(退避上限, 退避基数 × 2^(n-1))`；应用稳定运行超过重置时间后，
  下一次异常从头计数。
- 服务页「保活设置」按钮打开策略弹窗；策略持久化在 Host 状态里，只影响后续启动/接管与
  重试，打开或保存设置本身不会启动、停止任何应用。
- 宿主重启后无法确认旧进程状态，守护自动暂停；用户重新手动启动后恢复。

### 资源监控

- 对每个运行中的应用按进程组采样 CPU 与内存（默认 5 秒一次），保留最近 288 条
  内存历史，同时追加到指标文件；重启宿主后可从文件读取历史。
- 指标是近似值：CPU 可能超过 100%（多核），RSS 为进程组求和，共享页会重复计算。
- 平台暂不支持时显示“无数据”，不伪造 0。
- 概览按项目/应用聚合与排行；服务页逐应用显示 CPU/内存。
- 概览趋势使用按采样周期聚合的 CPU/RSS 总量（最近 120 点），只保留在内存中；
  宿主重启后从空开始，不伪造重启前的趋势。

### 日志

- 每个应用一份日志文件，按需读取尾部若干行，并支持跟踪新增内容。
- 输出必须能区分 stdout 与 stderr。
- 日志文件有大小上限，超限后轮转，避免长跑把一个文件写到几 GB。

### 面板

在 DSH 界面中提供一个左侧栏入口（服务坞）与它打开的全局页；页面内用五个 tab 区分功能：

- **概览·指标**：运行中 / 异常退出 / 已停止 / 需关注（异常、失联、需重启）/ 项目 / 应用 /
  语言 / 包管理器 / 总 CPU / 总内存 / 平均运行时长 / 最长运行共 12 项指标；状态构成环形图；
  语言与包管理器分布（实心段表示运行中）；技术栈（语言 × 包管理器）分布；CPU/RSS 趋势
  （最近 5 分钟）；宿主内存、负载、核心、运行时长与平台；项目负载表（语言/包管理器标签）
  与 CPU/内存排行；需要关注的服务及其原因；正在运行的服务、时长与资源。
- **概览·健康**：运行健康 hero（运行数、运行率、异常/失联/需重启、项目/语言/包管理器/
  平均运行时长、CPU/RSS 迷你趋势）；技术构成（语言、包管理器、技术栈）；资源趋势与宿主；
  紧凑版需要关注；项目负载与应用排行（CPU/内存可切换）；正在运行的服务。
- **服务**：一个项目一张卡片，卡片之间留出明确间隔；卡片头给出项目名、目录、应用数、运行中数量、项目语言标签与非托管应用数，并提供项目级批量操作（全部启动 / 全部停止 / 全部重启 / 一键接管）与整项目移除。卡片内每个应用一行，标出语言与包管理器标签、运行中应用显示托管/非托管徽标，状态、启动命令、工作目录与运行时长；托管应用可启停/重启/移除/查看日志，非托管应用可停止/重启/接管（重启与接管等价）但不提供日志。服务页顶部在存在非托管应用时显示「一键接管」，并提供「保活设置」与「同步」相邻；应用行展示守护中/等待重试/守护已停止。列表上方提供筛选条：按项目名/路径/应用名/命令搜索，按状态（全部/运行中/异常/已停止/非托管）快速过滤，按语言选择，并显示「已筛选/全部」项目数；筛选状态在切走 tab 再回来后保留；项目级批量操作只作用于当前筛选下可见的应用，避免「筛出来看着 3 个、实际动了 20 个」。
- **发现**：点「扫描」打开系统文件夹选择框，选目录后自动扫描；结果按项目/生态/应用分组，逐项展示理由。托管以项目为单位：可勾选项目批量托管、全选或全部托管。
- **日志**：选择应用与行数，查看最近日志并标出日志来源。服务列表里的「日志」就地打开弹窗查看（不离开当前 tab，Esc 与点击遮罩可关闭），整页日志 tab 仍然保留。

托管后操作的最小单位是应用；一个项目下的全部应用会随项目一起加入托管。

页头提供「输入框状态条」开关：关闭后输入框上方不再渲染状态条，选择由 Host 持久化，
刷新页面或重启宿主后保持。开关状态在所有会话间共享，不会每个对话各记一份。

### 给智能体

插件注册 13 个 `dockyard_*` 工具（扫描、加入项目、状态、项目汇总、启停、重启、日志、
指标、诊断），并注册一个 `dockyard` 技能，指导调试本机开发服务时优先使用本插件。
工具与技能都不把数据发往本机之外。

### 输入框上方状态条

输入框上方是一条与输入框**等宽对齐**的状态 bar，按块展示本机服务的实时概览：

- **身份**：服务坞图标与名称，左侧竖条用语义色标出整体健康度。
- **健康**：运行中/总数、异常数、失联数；异常与失联用对应语义色标签。
- **规模**：托管项目数。
- **资源**：运行中应用的 CPU 合计（带迷你进度条与阈值色）与 RSS 合计。
- **生态**：语言 + 包管理器分组标签与应用数，超出部分折叠成 `+N`，悬停可看完整分布。
- **操作**：展开/收起明细（只列需要关注与正在运行的应用），以及打开整页。

窄窗口先让生态块降级为「一组 + N」，并用「已停止」计数填补空档；更窄时依次舍弃生态、规模、资源，健康状态与操作始终保留。
空状态、加载中与状态接口不可用都有明确文案，不出现空白面板。状态条可在服务坞页头开关。

## 验收标准

以下每条都必须能实际演示，不接受"应该可以"：

| ---- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| A1   | 插件能被 DSH 安装并激活               | 安装结果 `application` 为 `applied`，窗口内无报错                                                                     |
| A2   | 扫描能识别项目/生态/应用并给出理由    | 产出三层结构与每个应用的判定理由                                                                                      |
| A3   | 启动一个长跑进程后状态变为运行中      | 启动后查询状态，进程 pid 与启动命令可读                                                                               |
| A4   | 关闭发起启动的客户端后服务仍然存活    | 启动后销毁调用方，再查询状态仍为运行中                                                                                |
| A5   | 停止能在超时内真正结束进程            | 停止后查询状态为已停止，且系统中该 pid 不存在                                                                         |
| A6   | 日志落文件且能按需读取                | 读到本次运行产生的输出，stdout 与 stderr 可区分                                                                       |
| A7   | 面板能在 DSH 界面中打开并显示真实数据 | 打开面板看到应用列表与状态，明暗主题下都可读                                                                          |
| A8   | 面板在未安装/无数据时不崩             | 空状态下显示文案而非空白或报错                                                                                        |
| A12  | 容器文件夹展开一层子仓库为项目        | 扫描含 8 个子仓库的普通文件夹，得到 8 个项目                                                                          |
| A13  | 混合项目按语言生态分成多个组          | Java Maven + Node 项目出现两个分组与各自应用                                                                          |
| A14  | 同一项目的不同 Node 包管理器分组正确  | yarn 与 pnpm 子包分别进入对应分组                                                                                     |
| A15  | 点扫描直接弹目录选择并自动开始扫描    | 桌面端不出现路径输入框，选完目录立刻有结果                                                                            |
| A9   | 左侧栏出现服务坞入口并能打开整页      | 入口可见，点击后主区域显示服务坞页面                                                                                  |
| A10  | 五个 tab 可切换且各自内容正确         | 概览·指标/概览·健康/服务/发现/日志逐个切换，数据与空状态正确                                                          |
| A11  | 页面内的启停操作即时反映到状态与日志  | 页面启动服务后状态变为运行中，日志能看到输出                                                                          |
| A16  | 服务页按项目卡片分组，标签信息完整    | 每个项目独立卡片；卡片头有语言标签，应用行有语言与包管理器标签                                                        |
| A17  | 项目级批量操作可用且失败不连坐        | 多应用项目点「全部启动」后其下应用全部运行；单个失败只汇总提示，其余照常执行                                          |
| A18  | 服务页筛选能快速定位项目              | 输入项目名只剩该项目；切「异常」只剩异常应用；选语言只剩该语言应用；计数与清除筛选正确                                |
| A19  | 服务页可就地看日志且保留整页日志      | 列表点「日志」弹出弹窗并持续刷新，Esc/遮罩可关；「日志」tab 仍可独立使用                                              |
| A20  | 状态条与输入框等宽且信息完整          | bar 左右边缘与输入框对齐；含运行/异常/失联、项目数、CPU/内存与语言/包管理器标签；明暗主题可读                         |
| A21  | 状态条可在插件内开关并跨重启保持      | 服务坞页头关闭后输入框上方不再渲染；刷新页面与重启宿主后仍为关闭                                                      |
| A22  | 两个概览 tab 的信息与图表完整         | 概览·指标含 12 项指标、状态/语言/包管理器/技术栈分布与 CPU/RSS 趋势；概览·健康含 hero、技术构成、资源与宿主、项目排行 |
| A23  | 概览分布与趋势口径一致且可降级        | 语言/包管理器/技术栈均来自已托管应用；无采样时趋势显示“暂无采样”，不画假线                                            |
| A24  | 非托管应用可见且可停止/重启           | 外部启动的应用显示「非托管」及 CPU/内存/端口；停止只杀外部进程；重启后转为托管运行；不提供日志                        |
| A25  | 手动接管三个入口且互不越界            | 顶部一键接管全部非托管；项目卡只接管本项目；应用行停止/重启只影响该应用；不启动项目内其他应用                         |
| A26  | 应用进程不随 DSH 退出而中断           | 启动应用后关闭 DSH，应用仍存活且日志继续写入；重新打开 DSH 后状态如实显示                                             |

## 已知限制（当前迭代）

- 只支持本机、单用户。多用户与远程访问不在范围内。
- 进程归属只在本进程存活期间有效：DSH 宿主进程重启后，之前托管的进程会失联，
  面板需要明确提示"失联"而不是谎报"正在运行"。
- 自动识别只覆盖声明式入口（package.json scripts 等），不解析任意脚本内容。
